# СтудМаршрут — MAX Hackathon MVP

**Команда:** MAXimum Care — Дмитриева Екатерина · Мыкало Валерия · Смирнова Екатерина
**Трек:** «Забота о людях»
**Формат:** чат-бот MAX + подключённое мини-приложение
**MAX-бот:** [@t659_hakaton_max_bot](https://max.ru/t659_hakaton_max_bot) · **Mini-app и API:** https://studroute-max.onrender.com
**Хостинг:** Render (Docker) · **Режим MAX:** webhook · **Языки:** RU / EN / 简体中文

## 1. Назначение

СтудМаршрут помогает конкретному сегменту — иностранному студенту 18+, впервые прибывшему на очное обучение в СПбГЭУ, — не пропустить административные шаги после приезда. Продукт собирает несколько параметров ситуации и строит персональный маршрут: что сделать, к какому сроку, почему, куда обратиться, что подготовить и где официальный источник.

MVP **не принимает официальных решений** и **не имитирует интеграции** с МВД или Госуслугами. Правила заранее проверены и хранятся в `data/rules.json`; каждое правило связано с источником из `data/sources.json` и датой проверки. Срок показывается, только если его называет источник; иначе карточка помечена «Без установленного срока».

## 2. Основной пользовательский сценарий

1. Пользователь запускает бота в MAX. Бот присылает приветствие и меню из кнопок:
   `🚀 Открыть СтудМаршрут` · `🧭 Мой маршрут` · `📋 После приезда` · `⚡ Изменились обстоятельства` · `🔗 Официальные источники` · `🌐 Язык` · `ℹ️ О проекте`.
2. Кнопка «🚀 Открыть СтудМаршрут» открывает подключённое mini-app (кнопка MAX `open_app`).
3. В mini-app пользователь видит короткий onboarding и отвечает на 5 вопросов: дата въезда, жильё, срок пребывания, гражданство Беларуси, виза и сроки документов. Для проверки есть кнопка «Пример для проверки».
4. Mini-app показывает дашборд: **ближайшее действие**, **ближайший установленный срок**, **прогресс** (выполнено / осталось / срочно) и предупреждения.
5. Карточка задачи отвечает: что сделать, когда, почему, куда обратиться, что подготовить, откуда срок, официальный источник. Кнопки: «Открыть официальный источник», «Отметить выполненным».
6. В разделе «Изменения» пользователь выбирает событие (новый въезд, гостиница/больница, переезд, новый паспорт) и дату — маршрут добавляет задачу со сроком 1 рабочий день.
7. Прогресс сохраняется на устройстве; маршрутом можно поделиться через MAX Bridge. В разделах «Справка» и «Источники» — контакты, документы, FAQ, термины и первоисточники.

## 3. Состав и архитектура

```text
MAX client (mobile / web)
   │  bot_started, message_created (кнопки меню типа message приходят как message_created)
   ▼
Node.js service (один контейнер, без runtime-зависимостей)
   ├── POST /webhook        приём событий MAX, проверка X-Max-Bot-Api-Secret
   ├── src/bot.js           меню, ответы RU/EN/ZH, кнопки open_app / link / message
   ├── src/rules-engine.js  детерминированный расчёт маршрута по data/rules.json
   ├── POST /api/route      персональный маршрут
   ├── GET  /api/sources    реестр официальных источников
   ├── GET  /api/meta       версия правил
   ├── POST /api/validate   HMAC-проверка WebAppData из MAX
   └── public/              mini-app: HTML/CSS/JS + MAX Bridge
          └── localStorage: ответы анкеты, отметки выполнения, язык
   │
   └──► MAX Bot API (platform-api2.max.ru): POST /messages, PATCH /me/commands, GET /me
```

| Компонент | Файлы | Роль |
|---|---|---|
| HTTP-сервер | `src/server.js` | статика mini-app, API, webhook |
| Бот | `src/bot.js`, `src/bot-texts.js` | меню, тексты на 3 языках, fallback кнопки mini-app |
| Движок правил | `src/rules-engine.js`, `src/date-utils.js` | применимость правил, расчёт дат, статусы |
| Данные | `data/rules.json`, `data/sources.json` | правила, тексты карточек, источники |
| MAX API | `src/max-api.js` | клиент Bot API с таймаутом и повтором на 429 |
| Валидация | `src/validation.js` | HMAC-SHA256 `WebAppData` |
| Mini-app | `public/index.html`, `public/app.js`, `public/i18n.js`, `public/styles.css` | интерфейс |

### Кнопки бота

| Кнопка | Тип MAX | Что делает |
|---|---|---|
| 🚀 Открыть СтудМаршрут | `open_app` | открывает mini-app бота; если клиент MAX отклонит кнопку, бот повторяет сообщение с кнопкой-ссылкой на mini-app |
| 🧭 Мой маршрут | `message` | объясняет, какие данные нужны, и даёт кнопку построения маршрута |
| 📋 После приезда | `message` | чек-лист первых шагов, собранный из `data/rules.json`, со сроками из источников |
| ⚡ Изменились обстоятельства | `message` | какие события нужно сообщить и в какой срок, кнопки mini-app и источника |
| 🔗 Официальные источники | `message` | список источников; ссылки — кнопками `link`, без длинных URL в тексте |
| 🌐 Язык | `message` | выбор Русский / English / 中文; язык запоминается |
| ℹ️ О проекте | `message` | команда, границы продукта, ссылка на GitHub |

Кнопки типа `message` отправляют свой текст в чат от имени пользователя, поэтому приходят как `message_created`: подписку webhook менять не нужно. Команды `/start`, `/menu`, `/help`, `/sources`, `/demo`, `/ru`, `/en`, `/zh` сохранены.

## 4. Запуск одной командой через Docker

```bash
cp .env.example .env      # укажите BOT_TOKEN и другие значения; .env не коммитится
docker compose up --build
```

- Mini-app: http://localhost:8080
- Healthcheck: http://localhost:8080/health

Для локальной демонстрации без MAX установите `ALLOW_DEMO=true`. Для разработки бота без публичного HTTPS: `npm run dev` (long polling).

## 5. Переменные окружения и порты

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен чат-бота MAX, только runtime secret |
| `BOT_MODE` | `webhook` для production, `polling` для разработки |
| `PORT` | HTTP-порт, по умолчанию `8080` |
| `APP_BASE_URL` | внешний HTTPS URL сервиса; используется для webhook и как запасная ссылка на mini-app |
| `WEBHOOK_SECRET` | секрет заголовка `X-Max-Bot-Api-Secret` |
| `ALLOW_DEMO` | разрешает демо без `WebAppData` |
| `MAX_API_BASE` | по умолчанию `https://platform-api2.max.ru` |

Порт: **8080/tcp**. Сервис один; база данных не нужна.

## 6. Зависимости

Node.js ≥ 20, стандартная библиотека и встроенный `fetch`. Runtime-зависимостей нет, поэтому `package.json` — полный список зависимостей. Тесты используют встроенный `node:test`. Docker-образ: `node:20-alpine` и российский корневой сертификат для MAX API с проверкой SHA-256.

## 7. Внешние сервисы и интеграции

- **MAX Bot API** — отправка сообщений, команды, webhook.
- **MAX Bridge** — `WebApp.openLink` для официальных ссылок, `WebApp.shareMaxContent` для sharing, `HapticFeedback` для отклика на действия, `initData` для проверки запуска.
- **Интеграций с МВД, Госуслугами, ЕГИССО или ИС вуза нет.** Используются заранее проверенные правила из официальных страниц СПбГЭУ и портала госуслуг Санкт-Петербурга (дата проверки — `checked_at` в `data/sources.json`).

## 8. Работа с данными

- Mini-app запрашивает только даты и ответы «да/нет». ФИО, паспортные данные, номера документов, фото и медицинские документы не собираются.
- Ответы, отметки выполнения и язык хранятся в `localStorage` устройства пользователя. Если хранилище недоступно, приложение работает без сохранения.
- Для расчёта маршрута ответы отправляются в `POST /api/route` и на сервере не сохраняются и не логируются.
- Бот хранит выбранный язык в памяти процесса (без записи на диск); после перезапуска язык берётся из `user_locale` MAX.
- `WebAppData` проверяется на сервере по HMAC-SHA256.

## 9. Тестовые данные

`test_data.json` содержит профили для проверки API и ожидаемые задачи. В mini-app кнопка «Пример для проверки» заполняет анкету профилем «общежитие, дольше 90 дней, виза», даты которого отсчитываются от текущего дня. Все данные модельные.

## 10. Пошаговая проверка

Автоматические проверки:

```bash
npm test
```

29 тестов: правила и сроки, отсутствие выдуманных сроков, валидация, полнота RU/EN/ZH в правилах, mini-app и боте, все кнопки меню на всех языках, и интеграционный тест webhook → бот → имитация MAX Bot API (включая повтор с кнопкой-ссылкой, если `open_app` отклонён).

Ручная проверка в MAX:

1. Откройте [@t659_hakaton_max_bot](https://max.ru/t659_hakaton_max_bot) и нажмите «Начать» — придёт приветствие с 7 кнопками.
2. Нажмите «📋 После приезда» — чек-лист со сроками и кнопкой официального источника.
3. Нажмите «🌐 Язык» → «中文» — меню и ответы переключатся на китайский.
4. Нажмите «🚀 Открыть СтудМаршрут» — откроется mini-app.
5. Нажмите «Пример для проверки» — появятся ближайшее действие, ближайший срок, прогресс и карточки.
6. В карточке раскройте «Подробнее», нажмите «Открыть официальный источник», затем «Отметить выполненным» — прогресс обновится и сохранится после перезагрузки.
7. «Изменения» → «Переехал(а)» → дата → «Добавить в маршрут» — появится задача со сроком 1 рабочий день.
8. Проверьте карточку ДМС: срок не показан, статус «Без установленного срока».
9. Переключите RU / EN / 中文 в шапке mini-app.
10. «Поделиться в MAX» — откроется системный экран sharing.

## 11. Webhook

```bash
npm run webhook:set   # регистрирует ${APP_BASE_URL}/webhook с WEBHOOK_SECRET
```

Подписка — `bot_started`, `message_created`. Production использует webhook; long polling — только для разработки. MAX требует доверенный TLS-сертификат.

## 12. API

Описание — `openapi.yaml` (OpenAPI 3.1). Обязательные проверки — `DATA-API.yaml`. Базовый адрес — https://studroute-max.onrender.com. Ролей и тестовых учётных записей нет.

## 13. Известные ограничения

- Один пилотный сегмент: иностранный студент СПбГЭУ в Санкт-Петербурге.
- Правила не обновляются автоматически; дата проверки показана пользователю.
- Праздничные нерабочие дни не учитываются: исключаются только суббота и воскресенье. Пользователь видит об этом предупреждение.
- Нет live-статусов из государственных информационных систем.
- Юридическая квалификация статуса пользователя не выполняется; пограничные случаи направляются к источнику и в отдел.
- Язык бота хранится в памяти процесса и может сброситься при перезапуске сервиса (тогда используется язык клиента MAX).
- Если тариф Render усыпляет сервис при простое, первый запрос после паузы обрабатывается дольше обычного.

## 15. Секреты

Рабочий токен и `WEBHOOK_SECRET` **не хранятся** в репозитории и задаются в переменных окружения Render. Значения для проверяющих передаются только в финальной презентации, как требует регламент, а не в Git.
