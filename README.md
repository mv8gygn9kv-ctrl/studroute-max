# СтудМаршрут — MAX Hackathon MVP

**Трек:** «Забота о людях»  
**Формат:** чат-бот + мини-приложение в MAX  
**Команда:** Дмитриева Екатерина · Мыкало Валерия · Смирнова Екатерина

## 1. Назначение

СтудМаршрут помогает конкретному сегменту — иностранному студенту 18+, впервые прибывшему на очное обучение в СПбГЭУ, — не пропустить административные шаги после приезда. Продукт собирает несколько параметров ситуации и строит персональную последовательность действий с дедлайнами, первоисточниками и отметками выполнения.

MVP **не принимает официальных решений** и **не имитирует интеграции** с МВД/Госуслугами. Правила заранее проверены и хранятся в `data/rules.json`; каждое правило связано с источником из `data/sources.json`.

## 2. Основной пользовательский сценарий

1. Пользователь запускает бота в MAX и открывает подключённое мини-приложение.
2. Указывает дату въезда, тип проживания, срок пребывания и визовый статус.
3. Получает маршрут: университетские шаги, ДМС, миграционный учёт, обязательные процедуры, продление визы/регистрации. Дата показывается только там, где она следует из первоисточника.
4. Отмечает выполненные пункты; прогресс хранится локально на устройстве.
5. При событии (переезд, новый паспорт, гостиница/больница, новый въезд) указывает дату — маршрут добавляет следующий срочный шаг.
6. Открывает официальный источник непосредственно из карточки задачи или делится маршрутом через MAX Bridge.

## 3. Состав и архитектура

```text
MAX chat bot
   │  bot_started / message_created
   ▼
Node.js service ──────────────► MAX Bot API (platform-api2.max.ru)
   │
   ├── /webhook   production updates
   ├── /api/validate  HMAC verification of MAX WebAppData
   ├── /api/route     deterministic rules engine
   └── /api/sources   curated source registry
   │
   ▼
MAX mini-app (HTML/CSS/JS + MAX Bridge)
   │
   └── localStorage: profile + task completion only
```

В проекте нет сторонних runtime-зависимостей: используется Node.js 20 и стандартный `fetch`. Это сокращает поверхность атаки и время сборки Docker.

## 4. Запуск одной командой через Docker

1. Скопируйте пример окружения:

```bash
cp .env.example .env
```

2. В `.env` укажите `BOT_TOKEN` и другие параметры. **Не добавляйте `.env` в Git.**

3. Запуск:

```bash
docker compose up --build
```

Мини-приложение: `http://localhost:8080`  
Healthcheck: `http://localhost:8080/health`

Для локальной демонстрации без MAX можно установить `ALLOW_DEMO=true`.

## 5. Переменные окружения

- `BOT_TOKEN` — токен чат-бота MAX. Только runtime secret.
- `BOT_MODE` — `webhook` для размещённой версии, `polling` для локальной разработки.
- `PORT` — HTTP-порт, по умолчанию `8080`.
- `APP_BASE_URL` — внешний HTTPS URL сервиса.
- `WEBHOOK_SECRET` — секрет подписи входящих webhook-запросов.
- `ALLOW_DEMO` — разрешает внешнюю демонстрацию без валидного `WebAppData`.
- `MAX_API_BASE` — по умолчанию `https://platform-api2.max.ru`.

## 6. Внешние сервисы и интеграции

- MAX Bot API — отправка сообщений, команды, webhook/long polling.
- MAX Bridge — получение launch context, открытие официальных ссылок и sharing.
- Реальных интеграций с МВД, Госуслугами, ЕГИССО или вузовской ИС в MVP нет.

## 7. Работа с данными

MVP запрашивает только данные, необходимые для маршрута: даты и категориальные признаки. Полные ФИО, паспортные данные, медицинские документы и номера документов не собираются. Выполненные задачи сохраняются в `localStorage` браузера пользователя. При запуске в MAX параметр `WebAppData` проверяется на сервере по HMAC-SHA256 согласно документации MAX.

## 8. Тестовые данные

Готовые сценарии находятся в `test_data.json`. Пример: общежитие + пребывание >90 дней + учебная виза.

## 9. Проверка

```bash
npm test
```

Пошаговая проверка MVP:

1. Откройте `/`.
2. Выберите общежитие, >90 дней, не Беларусь, нужна виза.
3. Укажите дату въезда 2026-09-01, окончание визы 2026-11-30, окончание регистрации 2026-11-30.
4. Нажмите «Построить маршрут».
5. Убедитесь, что присутствуют задачи первичного учёта, обязательных процедур и продлений.
6. Отметьте одну задачу выполненной — прогресс должен сохраниться после перезагрузки.
7. В разделе «Событие» задайте дату 2026-09-18 — появится задача с организационным сроком 1 рабочий день.
8. Откройте первоисточник из карточки.
9. В MAX нажмите «Поделиться маршрутом» — должен открыться системный экран sharing.
10. Откройте карточку ДМС и убедитесь, что для неё не показан выдуманный дедлайн: источник не называет конкретную дату.

## 10. Webhook

После размещения сервиса на публичном HTTPS-домене:

```bash
npm run webhook:set
```

MAX требует доверенный TLS-сертификат. Для production используйте `BOT_MODE=webhook`; long polling оставлен только для разработки.

## 11. API

Описание — `openapi.yaml`. Проверки для хакатона — `DATA-API.yaml`. В проекте нет ролей и тестовых аккаунтов.

## 12. Известные ограничения

- MVP покрывает один пилотный сегмент: иностранный студент СПбГЭУ в Санкт-Петербурге.
- Правила не обновляются автоматически: дата проверки показана пользователю.
- Праздничные нерабочие дни в расчёте «рабочих дней» пока не учитываются; исключаются только суббота и воскресенье. Для production нужен производственный календарь.
- Нет live-статусов из государственных информационных систем.
- Не выполняется юридическая квалификация статуса пользователя; пограничные случаи направляются к первоисточнику/ответственной организации.

## 13. Остановка и повторный запуск

Остановка:

```bash
docker compose down
```

Повторный запуск:

```bash
docker compose up --build
```

## 14. Секреты

Рабочий токен **не хранится** в репозитории. Для сдачи он вводится через переменную окружения хостинга. Если регламент требует передать токен проверяющим на первом техническом слайде презентации, добавьте его только в финальную версию презентации, а не в Git.
