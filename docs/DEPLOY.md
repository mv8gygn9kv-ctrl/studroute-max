# Деплой и подключение к MAX

## Что уже готово

Приложение является единым Node.js-сервисом: оно отдаёт mini-app, API маршрута и webhook endpoint для бота. Нужен один публичный HTTPS URL.

## 1. Разверните контейнер

Подойдёт любой хостинг, который запускает Docker/Node.js и выдаёт постоянный HTTPS-домен. В официальной документации MAX среди примеров хостинга mini-app упоминаются VK Cloud, GitHub Pages и Yandex Cloud; для этого проекта нужен backend, поэтому выбирайте вариант с запуском Node.js/Docker, а не только статических файлов.

Переменные production:

```text
BOT_TOKEN=<токен, выданный организаторами>
BOT_MODE=webhook
PORT=8080
APP_BASE_URL=https://<ваш-домен>
WEBHOOK_SECRET=change_me_5_to_256_chars
ALLOW_DEMO=false
MAX_API_BASE=https://platform-api2.max.ru
```

Рабочий токен не коммитьте и не записывайте в `.env.example`.

## 2. Проверка после деплоя

```bash
curl https://<ваш-домен>/health
```

Ожидается JSON с `"ok": true`.

Затем запустите:

```bash
npm run bot:me
npm run webhook:set
```

Первый скрипт проверяет токен через `GET /me`, второй регистрирует `https://<ваш-домен>/webhook`.

## 3. Подключите mini-app к выданному боту

В настройках бота MAX укажите `https://<ваш-домен>` как URL мини-приложения и выберите кнопку `Открыть` или `Старт`. MAX требует HTTPS. Если в хакатоне привязка URL выполняется через организаторов, используйте выданную форму для URL вместо изменения настроек самостоятельно.

## 4. Финальная проверка

Проверьте сценарий в мобильном MAX и web MAX: старт бота → кнопка mini-app → onboarding → маршрут → официальный источник → отметка выполнения → событие → пересчёт → sharing.

## 5. После успешного теста

Зафиксируйте Git commit hash либо SHA-256 архива, внесите реальные ссылки в `openapi.yaml`, `DATA-API.yaml` и первый технический слайд презентации. После дедлайна зафиксированную версию не меняйте.
